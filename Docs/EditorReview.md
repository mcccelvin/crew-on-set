# Editing and pre-export review

`EditorManager` adds a BACK control to the existing review panel, in the left top margin opposite the authored Submit control. `BackToEditor` stops/cancels review playback, closes only that panel, returns the free cursor and refreshes the program monitor. It does not reload the scene, clear clips, trims, branding, chosen music or grades, apply money, or submit a result. Exporting again rebuilds the sequence and pending scores from the revised timeline. `SubmitVideo` ignores calls outside a ready review (including compilation or a closed preview).

The first-commercial lesson describes BACK / edit / EXPORT / SUBMIT. `EditorTutorialManager.OnReviewBack` cancels any pending review-dialogue transition, hides its tasks and releases the lesson's editing restrictions while revising. Re-export restores the review lesson before submission. `EditorTutorialInputGate` explicitly permits the Back control in the review, without skipping the earlier tutorial tasks. Career and copied crew editors use the same implementation; host/role and grading authority remain unchanged.

`TruePixelPlayer` scopes placed branding to its monitor, or the editor monitor explicitly supplied by the review player. `VideoFrameCompositor` flattens the existing graphic meshes into a render texture at the source footage resolution. It resets from the source frame on every composition, then draws placed overlays with their existing sprite/text material, actual monitor-local geometry, order and CanvasGroup alpha. Texture bounds clip the graphics; scene UI stencil masks, title-safe guides, timeline handles and bin items are not part of the video. No interactive overlay copies are instantiated in review. Color grading, UV camera movement and transitions apply to the resulting image, not a separate floating graphic layer. The original source tapes are not overwritten, and this does not add an external MP4 encoder.

Overlay visibility uses frame indices on the timeline (start inclusive, end exclusive), including clip offsets and trims. Playback suppresses the original authoring graphics while their pixels are shown in the composed video. Stop, Back, disabling and destruction restore their renderers; returning a graphic to the bin also restores its normal display. Rendering resources are released on destruction. This path uses runtime Unity APIs only and requires no new shader, layer or offscreen camera.

## Verification

`TimelineRuler` and `TimelineRulerTick` make the timestamp row clickable/draggable. Exact number clicks seek to that second; background dragging uses ruler-local coordinates and the current pixels-per-second. `TimelineSeekMath` maps the timeline into compiled footage with trims and gaps; seeking pauses preview, updates graphics and never counts as watching a tutorial preview through its end. A pending seek follows compilation, with the latest requested time winning. Empty timelines show black without compiling an empty tape.

`EditorUndoHistory` belongs to the current `EditorManager`, including the copied crew editor. It stores up to 64 gesture-level edits, not every drag frame. `EditorEditSnapshot` records changed clip, branding, grade and effect data only, and keeps timeline geometry in seconds so adaptive zoom cannot distort an undo. Restoring a removed branding card reconnects its retained overlay; undoing a split removes only the new split piece. Input fields keep their own Ctrl+Z, and pause, Boss/contract modals and final review block editor undo. Selection, playback, ruler seeking and tab changes are not history entries. Tutorial undo is limited to the current task so completed prerequisites cannot be removed; the first-commercial lesson includes an actual seek task and a move/undo exercise. Contract 4 retains split/undo counters for its lesson.

The chat's `feedback-review-check.ps1` compiles all affected runtime code against actual Unity Editor and standalone-player references plus editor tools. `editor-review-check.ps1` exercises extracted Back/revision methods with UI dependencies stubbed and checks authored control bounds and source routing. `EditorReviewVerification.Run` (Crew-On-Set / Testing / Verify Embedded Review Graphics) creates an isolated preview scene to check actual GPU pixels, Y alignment, alpha, source-monitor resizing/pivots, output clipping, base-frame preservation and repeated composition. It never opens or replaces the current game scene. Its menu output goes to `Logs/EditorReview`; `-reviewOutput` may override that path for automated checks. The isolated batch fixture uses the actual compositor and actual Unity UI assembly; only its overlay timing/data dependency is stubbed. GPU pixel checks are not a full scene/playback/build test.

A full live edit/export/back/re-export/submit loop, animated branding, color changes, pause/resume and a two-client crew test still need testing in the game. Stop Play, import the scripts, test both a passing and failing delivery, then make a fresh player build. Existing executables cannot acquire new controls or compositing code.
