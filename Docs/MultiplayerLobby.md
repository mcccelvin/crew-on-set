# Multiplayer lobby scene

Multiplayer is unlocked by completing Contract 1 in singleplayer on the current
save account. Both host/join entry points check saved tutorial completion.
Multiplayer contract selection starts at Contract 2 and cycles through 2–5;
the solo tutorial cannot be selected or started in a crew room.

Create/join stays in Main Menu. `MultiplayerWaitingLobby` replaces the content inside GameSaveMenu's existing authored folder; it adds no separate canvas, backdrop, modal panel or header artwork. The existing X and Escape leave the room. The authoritative room snapshot uses phase `waiting`; players can ready up without selecting roles. The host's START requires 2–4 ready players and advances the snapshot to `lobby`. Only after the server property acknowledgement does the host close room entry and load `MultiplayerLobby` for synchronized role selection.

The role-selection scene uses a full-screen 3D studio presentation, with the legacy Help Desk tablet and paper-backdrop graphics hidden. `CrewSelectionStage` builds an isolated perspective camera, velvet backdrop, lit platform and an idle-animated customized character. Rotation buttons turn this preview; role changes do not change its outfit. Paper-and-gold role panels and teammate portraits remain in screen space. No gameplay studio/player spawner runs here. After roles are assigned and confirmed, START CONTRACT loads SingleStudio through the same acknowledgement path. `MultiplayerRoleManager` creates gameplay studio services only in the shared studio, never in Main Menu or MultiplayerLobby.

Role selection shows a full-body customized local avatar, role responsibilities and controls, four role choices, and four teammate portrait cards with usernames, assigned roles and readiness. Roles can be inspected while locked or owned by another player; only unlocked available/local roles send assignment commands. Smaller crews can still claim multiple roles. `CrewPlayerIdentity` publishes the account username as Photon NickName and equipped cosmetic IDs in the player's `COS.Outfit.V1` property. Teammate portraits reuse AccountAvatarPortrait with isolated render stages, rebuilding only when the player's outfit changes. The main character is a live 3D model. Role changes never change the character or outfit.

Both stages use the existing authoritative room snapshot. The new manager in each scene restores the snapshot (roles, budget, contract and briefing) rather than keeping scene objects alive. Leaving/disconnecting returns to Main Menu; host migration republishes the room state through the same start path. Legacy direct studio entry retains its lobby fallback.

All synchronized scene loads announce reliable event 175 to the other room members before Photon starts loading. Every client installs the listener at startup, so joiners get the same loading overlay even if they have never loaded a scene locally. Photon still controls synchronized scene activation.

Both modes use the actual SingleStudio scene. `SingleStudioMultiplayerBootstrap` is attached to StudioSetup and runs before solo Awake/Start. With a Photon room active, it disables the solo Controllers, UI and Player roots, disables career input on physical stations, cancels the solo arrival tour and installs PUNSpawner. The authored environment is used directly; no duplicate room prefab is instantiated. Without a room, the bootstrap does nothing. Station views still use independent room-owned UI copies. MultiStudio is no longer a gameplay destination or build entry and can be deleted. The previous environment-copy builder remains a manual legacy tool and no longer rebuilds automatically.

Boss dialogue progress is stored on each CrewMember, rather than advancing the shared legacy briefingPage. A player's Space press advances only their page. Finishing closes that player's dialogue and immediately permits studio gameplay; unfinished readers retain their Boss panel and progress. The first finished member opens the room's build phase, with server-side interaction permission still gated by each sender's own briefed flag. Fresh contracts and retries reset each member's progress.
