## Menu motion

`MainMenuMotion` restores the Crew On Set title's original animated entrance and looping vertical drift; menu entries still use continuous staggered easing. `UITransition` uses a short horizontal slide, crossfade and subtle uniform zoom for panels in Main Menu and Account, including Play/Join/Create, saved games, shared settings and the profile career card. Closing uses `UITransition.Hide`: the visible window and its animated content slide/fade out over 0.24 seconds, then deactivate and restore their authored alpha, position, scale and interaction settings. Controls are locked during the exit; repeated Close/Back/Escape does not repeat callbacks. Reopening cancels a pending exit, including its stale callback. `UIMotionInstaller` redirects authored ancestor-hiding Close/Cancel button events through this path; save dialogs, settings and the menu profile use it directly. Profile/input cleanup and settings close callbacks run after the exit or once if the window is externally disabled. Root canvases only fade so the stage and screen geometry stay fixed. `UIButtonFeedback` eases menu hover/press states without squash or overshoot. All timing uses unscaled time; other gameplay scenes retain their existing transitions and immediate hiding. The removed moving-paper effect stays disabled.

## Account sign-in

`AccountManager.Awake` applies `LoginScreenPresentation` in the Login scene only. At the player's request, the original paper/wood/pen/paperclip artwork and centered authored layout are restored. The rejected production-sheet/slate redesign is no longer created. Only live text is improved: bundled Liberation Sans, dark input text, clear white primary-button lettering, readable blue links, corrected password placeholder and signup caption. Original RectTransforms, image sprites, visibility and canvas scaling are unchanged; baked background headings remain original artwork. Input text retains the icon-side inset but loses the old vertical padding that clipped letters; signup text offsets are preserved. Focused fields remain light enough to read, and reapplying typography preserves drafts.

The authored login SIGN UP button has one persistent call: `AccountManager.OnWebsiteSignUpPressed`. It opens `https://crew-on-set.vercel.app/signup` using `Application.OpenURL` and leaves sign-in visible for the player's return. `OnRegisterPressed` also routes there for older event bindings; the legacy `Register` API and serialized fields remain for compatibility. Login, recovery, exit and `GameSaveManager.SetAccount` retain their original behavior. Each `ChangeInput` binds to its own form's email and submit button. No credentials are placed in the URL.

Verification: the restored text-only version compiles with actual Unity editor and standalone-player references. A separate native scene check passed 83 assertions covering preservation of every authored RectTransform/visibility, original image sprites and canvas scaling, no new card/slate, retained drafts, readable fonts/focus, corrected hints and the exact website signup event/URL. The original-layout 1280x720 render was inspected. Browser launch and live authentication were not exercised; this is not a full game build. The rejected redesign's screenshots are not evidence of the current layout.

## Shared settings

Main-menu Options and pause-menu Options instantiate `SharedOptionsPanel` from `Assets/Script/SharedOptionsPanel.cs`. `MainMenuOptionsHost.cs` wires the inactive main-menu entry point on scene load; `PauseManager.cs` owns the pause entry point; `GameOptions.cs` applies global settings. Both views use the supplied OPTIONS.psd frame, tabs, slider and action-button artwork and the same global Options.* preferences. SAVE applies and persists all draft settings; RESET stages defaults; X/Escape cancels. Closing in-game settings preserves the pause state.

General: logarithmic mouse sensitivity and controls reference. Audio: master volume through AudioListener. Graphics: fullscreen, Unity quality level and frame-rate cap. Separate music/SFX/voice buses and keyboard rebinding are not presented as working controls. Fullscreen applies in standalone builds.

## PSD contract and Almanac design

The supplied Almanac.psd, CONTRACT.psd and CONTRACT2.psd artwork is extracted into `Assets/UI/UI-EXPORT/PSD Pieces`. The original cover, parchment, metallic rings, five colored ribbons, closed folder, open folder/paper stack and taped photo frame are used directly. Photoshop sample copy and transparency checkerboards are not included. The runtime catalog references these textures for builds.

All five contract introductions use a three-folder selector with arrows and SELECT. Only the current job can be selected. SELECT opens a production agreement organized into Pre-Production, Production, Post-Production, Budget and Payment, and Delivery and Approval. There is no `CONTRACT n / 5` counter. The bottom signature footer owns ACCEPT, disabled until the scroll reaches the document bottom. Scrolling alone and TAB/closing never accept an unsigned agreement. Clicking the enabled button reveals the player's name with a moving pen and ink line, confirms the signed date, then invokes the original acceptance callback exactly once. Scrolling and repeated signing clicks are locked during that animation; it uses unscaled time and waits while paused. Runtime initialization upgrades baked briefs as well as generated panels. Subsequent TAB reviews show the signed name/date without signing or paying again. `ContractSignature.<level>.Name` and `.Date` use career-local `GameSavePrefs`; the signer comes from the global `PlayerName`, with an offline Player fallback. Contract requirements and economy values remain live game data, not the PSD's sample 60,000 budget.

ACCEPT uses the folder's accent: Artisan olive, Goke cola red, Terrari racing red, Kape Kultura coffee brown, Haraya rose. `ExportUIArt.GetTintable` caches a neutral copy of the existing blue button, preserving its alpha, black outline and bevel shading; the imported artwork is unchanged. `ContractUIManager.StyleContractAcceptButton` applies the active contract theme to both baked and runtime buttons when refreshing the signature. Hover, pressed and disabled states remain tinted variants of that theme. The shorter label does not change signing, scroll gating or acceptance callbacks.

The contract signature uses the account display name cached in `PlayerName`, never the email or career/save name. Both login implementations request the PlayFab profile/account fields and fall back from display name to username. Offline signing retains the cached account name; a genuinely empty identity uses `Offline Player`. The bordered paper signature area uses a blue-ink Allura cursive signature and a separate, readable printed account name. `Assets/Resources/ContractFonts/Allura-Regular.ttf` and its SIL OFL license are bundled for standalone/offline use; a cached dynamic TMP font supplies the cursive glyphs, with existing game font fallbacks. Old generic Player/Guest signatures are displayed using the real cached account name when available without reaccepting or issuing another payment.

The Almanac uses EQUIPMENTS and TECHNIQUES tabs, illustrated category ribbons and pagination of unlocked beginner instructions. Player records and achievements have moved out of the book to the Profile HUD button above the coins (I shortcut). `AlmanacProfile.cs` builds the separate screen with the original profile background, label, icon, back and exit artwork. The existing record and achievement data is reused; Escape or Back restores gameplay input. Artwork is from the PSD; entry text is dynamic and other products use available artwork or a name placeholder in the photo frame.

Validation: editor/player compilation and isolated Unity checks for texture loading, strip-card duplication prevention, price/cart listener, contract lock protection, brief scrolling and exactly-once acceptance. 1920x1080 renders of the Almanac, selector and brief are reviewed separately from the live studio scene.


The profile is authored in SingleStudio at UI/GameUI/Player Profile; the icon is UI/GameUI/PlayerUI/Profile HUD. Serialized profile references and persistent button events retain Inspector edits. `AlmanacProfileProgress` and `AlmanacProfileAccount` reuse the authored screen with the original Profile/Stats/Shop paper/title artwork and icon sidebar. Achievements open from Stats. The main-menu Account entry opens the same screen through `AccountProfileMenuHost`; Name/Bio/ID are account-wide, while stats and achievement rows remain selected-career data. Main-menu career selection is read-only. See `Docs/PlayerProfile.md` for identity syncing, event hooks, lifetime totals and older-save limits.
